# Карточная игра «Дурак»

Сетевая карточная игра «Дурак» на двух игроков с режимом одиночной игры против бота. Клиент — статические HTML/CSS/JS, сервер — Node.js (Express + Socket.io). Аккаунты и сохранение игры — встроенная файловая БД, без внешних зависимостей.

## Возможности

- Регистрация и вход по логину/паролю; автоматический вход по токену сессии.
- Сохранение партии в БД после каждого хода — можно выйти и вернуться к той же позиции.
- Игра по сети для двух игроков через систему лобби (создание и вход по коду).
- Одиночная игра против бота с лёгким уровнем сложности.
- Колода из 36 карт, автоматическое определение козыря, раздача по 6 карт.
- Серверная проверка ходов: атака, защита, взятие карт, смена ролей, добор из колоды.
- Звуковое сопровождение действий (атака, защита, взятие карт, клики) с регулировкой громкости.

## Установка и запуск

Требуется Node.js 18+.

```bash
cd server
npm install
npm start
```

После запуска сервер слушает порт `3000` (или порт из переменной окружения `PORT`).
Откройте в браузере: <http://localhost:3000>.

Дополнительных зависимостей сверх `express` и `socket.io` не нужно — БД работает на встроенном `fs`/`crypto`.

## Аккаунты и сохранение игры

- На стартовом экране две вкладки: **Вход** и **Регистрация**. Логин — 3–20 символов (буквы/цифры/`_`/`-`), пароль — минимум 4 символа.
- Пароли хранятся как `scrypt`-хеш с уникальной солью на каждого пользователя.
- После входа клиент получает токен сессии и сохраняет его в `localStorage` — при следующем открытии страницы вход происходит автоматически.
- У каждого пользователя может быть **одна** незаконченная партия одновременно. Если она есть — над вкладками лобби появляется панель «Продолжить игру / Удалить сохранение».
- Состояние игры (колода, карты на руках, карты на столе, козырь, чей ход, кто атакует/защищается) сохраняется в `server/data/db.json` после каждого хода.
- Если оба игрока вышли — лобби выгружается из памяти, но остаётся в БД и поднимается, когда любой из них нажмёт «Продолжить».
- При сетевом обрыве клиент автоматически переподключается и реавторизуется — если в этот момент шла партия, сокет автоматически возвращается в её лобби.

## Как играть

После авторизации доступны три вкладки лобби:

1. **Создать лобби** — игра запускается с вашим логином в качестве имени, вы получаете 6-значный код. Передайте код второму игроку.
2. **Войти по коду** — введите код существующего лобби.
3. **Против бота** — одиночная игра, партия запускается сразу.

Правила игры стандартные для «Дурака»:

- Атакующий выкладывает карту на стол.
- Защищающийся бьёт её картой той же масти большего достоинства либо козырем.
- Если отбиться нечем — забирает карты со стола кнопкой «Взять карты».
- Когда все карты отбиты, раунд завершается, роли меняются, игроки добирают карты до 6 из колоды.
- Побеждает тот, кто первым избавится от всех карт, когда колода пуста.

## Режим игры с ботом

Бот — отдельный модуль ([server/bot.js](server/bot.js)). Лёгкий уровень сложности:

- **В атаке** играет младшую карту в руке, предпочитая некозырные.
- **В защите** бьёт младшей подходящей картой (некозырные — в первую очередь).
- Если отбиться нечем — забирает карты со стола.
- Не подкидывает лишнее, не «придерживает» козыри, не анализирует руку соперника.

Ходы бота отрабатываются на сервере с паузой ~0.9 с после каждого действия игрока. Партии с ботом тоже сохраняются — можно прервать и вернуться позже.

## Архитектура

### Socket.io-события клиент → сервер

| Событие | Назначение |
|---|---|
| `register` | Создать аккаунт |
| `login` | Войти по логину/паролю |
| `authByToken` | Войти по сохранённому токену сессии |
| `logout` | Завершить сессию |
| `createLobby` | Создать лобби 2×2 |
| `joinLobby` | Войти в лобби по коду |
| `createBotLobby` | Создать одиночную партию против бота |
| `resumeGame` | Вернуться в свою сохранённую партию |
| `abandonGame` | Удалить сохранённую партию |
| `playCard` | Сыграть карту (атака/защита) |
| `takeCards` | Взять карты со стола |

### Socket.io-события сервер → клиент

`authSuccess`, `authError`, `lobbyCreated`, `gameJoined`, `gameAbandoned`, `lobbyError`, `gameStateUpdate`, `gameFinished`, `moveError`, `playerLeft`.

### Состояние в памяти

- `lobbies: Map<code, { game, vsBot, botId, sockets: { username → socketId } }>` — активные партии.
- `socketInfo: Map<socketId, { username, code }>` — обратная привязка для обработчиков ходов и disconnect.
- Идентификатор игрока внутри `CardGame` — это `username` (стабильный), а не `socket.id`, поэтому переподключение не «теряет» игрока.

### Слой персистентности — `server/db.js`

Один JSON-файл `server/data/db.json` с четырьмя коллекциями:

- `users` — `{ username, salt, passwordHash, createdAt }`
- `sessions` — `token → { username, createdAt }`
- `games` — `code → { vsBot, status, state, player1, player2, updatedAt }`, где `state` — результат `CardGame.toJSON()`
- `activeGames` — `username → code` (последняя незаконченная партия пользователя)

Запись атомарная: пишем во временный файл `db.json.tmp`, затем `rename`. Запросы на сохранение объединяются в одну запись с дебаунсом ~100 мс, плюс синхронный сброс при `SIGINT`/`SIGTERM`/`exit`. Публичный API модуля компактный — при желании заменить файловое хранилище на SQLite/Postgres достаточно переписать тело `db.js`.

### Поведение при выходе игрока

- При `disconnect` сервер **не удаляет** игрока из `CardGame` — рвётся только привязка сокета. Второй игрок получает событие `playerLeft` с сообщением «Игрок вышел. Прогресс сохранён».
- Если онлайн никого не осталось — лобби выгружается из памяти (в БД остаётся).
- При следующем входе любого из участников лобби поднимается из БД, сокет привязывается обратно, партия продолжается.

## Известные ограничения

- Партия идёт строго на двух игроков; «подкидной» режим на нескольких атакующих не поддерживается.
- На одного пользователя одновременно — только одна незаконченная партия (новую можно создать после завершения или удаления старой).
- Файловая БД рассчитана на небольшой проект на одной машине; для продакшена с реальной нагрузкой стоит заменить `server/db.js` на SQLite/Postgres.
- Карты в `gameStateUpdate` рассылаются всем в комнате — теоретически клиент мог бы посмотреть руку соперника в сетевой панели. Если важно — нужно фильтровать состояние перед отправкой.
